### Технический отчет по проекту «Call Analysis Pipeline»

Проект представляет собой автоматизированную систему речевой аналитики для колл-центра медицинской клиники. Система предназначена для обработки записей телефонных разговоров, их транскрибации, анализа эмоционального фона и автоматической оценки качества работы операторов.

#### 1. Архитектура системы
Система построена по принципу **«Диспетчер — Воркер»**, что позволяет параллельно обрабатывать большое количество звонков:

*   **Dispatcher (`src/dispatcher.py`)**: Фоновый процесс, который сканирует хранилище (параметр `RECORDS_ROOT`). Он сопоставляет файлы в папке с базой данных PostgreSQL и отправляет новые записи в пул воркеров.
*   **Worker (`src/worker.py`)**: Выполняет полный цикл обработки одного аудиофайла.
*   **Базы данных**:
    *   **MySQL**: Служит источником метаданных о звонках (длительность, дата, номера телефонов) из существующей АТС.
    *   **PostgreSQL**: Основное хранилище результатов анализа (тексты, эмоции, оценки LLM).

#### 2. Технологический стек (ML-компоненты)
*   **Транскрибация (ASR)**: `faster-whisper` (модель `large-v3-turbo`). Обеспечивает высокую скорость и точность распознавания русской речи.
*   **Анализ эмоций**: `GigaAMEmo` (SberDevices). Классифицирует голос на категории: нейтральный, позитивный, негативный, конфликт.
*   **Смысловой анализ (LLM)**: `Saiga Llama3 8B` (формат GGUF). Используется для экспертной оценки диалога и извлечения данных.
*   **Frontend**: `Streamlit` — на нем реализован дашборд для визуализации статистики.

#### 3. Детальный разбор этапов обработки

**Этап 1: Разделение каналов**
Система ожидает **стерео-запись**, где левый канал — оператор, правый — клиент. Воркер разделяет их на два моно-файла, что позволяет точно закрепить каждую фразу за конкретным участником диалога.

**Этап 2: Транскрибация и эмоции**
Каждый канал обрабатывается моделью Whisper. Для каждого найденного фрагмента речи (сегмента):
1. Извлекается текст.
2. Соответствующий аудио-отрезок подается в модель `GigaAMEmo`.
3. В базу записывается фраза с временной меткой, ролью (оператор/клиент) и эмоциональной окраской.

**Этап 3: AI-аудит (LLM)**
Весь диалог собирается в текстовый блок и передается в LLM `Saiga`. На основе сложного промпта модель возвращает JSON-отчет, включающий:
*   **Politeness score**: Оценка вежливости от 0 до 10.
*   **Call purpose**: Цель звонка (запись, консультация, жалоба и др.).
*   **Checklist**: Проверка обязательных элементов (приветствие, представление, выявление потребности, озвучивание цены, отработка возражений, прощание).
*   **Summary**: Краткое содержание разговора.

**Этап 4: Дашборд (`dashboard/dashboard.py`)**
Визуализирует накопленные данные, позволяя руководителю видеть среднюю вежливость по клинике, распределение целей звонков и результаты выполнения чек-листов операторами.

#### 4. Особенности реализации
*   **Эффективность**: Код оптимизирован для работы на CPU (используются квантованные модели `int8` и `q4_K_M`).
*   **Отказоустойчивость**: Состояния обработки (`processing`, `done`, `error`) фиксируются в БД, что позволяет системе корректно продолжать работу после сбоев.
*   **Масштабируемость**: Количество параллельных воркеров настраивается через переменную `NUM_WORKERS` в `.env`.

#### 5. Итог анализа
Проект является готовым Pipeline-решением для автоматизации контроля качества. Он не просто переводит речь в текст, а выполняет глубокую смысловую оценку, заменяя ручной прослушиватель звонков. Код написан структурированно, с четким разделением ответственности между модулями.
