# Call Analysis Pipeline

Автоматическая система анализа телефонных разговоров колл-центра медицинской клиники на базе ИИ.

## Возможности
- **Транскрибация**: Высокоточное распознавание русской речи с использованием GigaAM v3.
- **Интеллектуальный анализ**: Определение цели звонка, оценка вежливости оператора, проверка по чек-листу с помощью Qwen2.5 (LLM).
- **Двухканальная обработка**: Раздельный анализ голоса оператора и клиента (стерео-записи).
- **Масштабируемость**: Раздельные конвейеры распознавания и анализа для оптимальной загрузки CPU.
- **Интерактивный дашборд**: Визуализация результатов, прослушивание звонков и управление задачами.

---

## Порядок работы системы

### Технический Workflow (Конвейер обработки)

Система работает в фоновом режиме как набор диспетчеров и воркеров:

1.  **Сканирование**:
    - `asr_dispatcher` постоянно отслеживает появление новых файлов в директории `RECORDS_ROOT` (за сегодня и вчера) и проверяет таблицу `tasks` на наличие исторических заданий.
2.  **Распознавание (ASR)**:
    - При обнаружении нового звонка запускается `asr_worker`.
    - Аудио загружается в память, каналы разделяются (левый — оператор, правый — клиент).
    - Выполняется нормализация громкости и сегментация (VAD).
    - Модель GigaAM v3 преобразует речь в текст с временными метками.
    - Результат сохраняется в таблицы `calls` и `transcripts`, статус звонка меняется на `transcribed`.
3.  **Анализ (LLM)**:
    - `llm_dispatcher` находит звонки со статусом `transcribed`.
    - `llm_worker` проверяет номер телефона по белому списку (таблица `phones`). Если номера нет в списке и не задан флаг "анализировать всё", звонок помечается как `skipped`.
    - Если звонок подлежит анализу, LLM (Qwen2.5) обрабатывает транскрипт согласно заданному промпту.
    - Итоговые оценки сохраняются в `evaluations`, статус меняется на `processed`.

### Пользовательский сценарий

1.  **Запуск системы**:
    - Система работает как системная служба Linux (`call_analysis.service`). После настройки она автоматически обрабатывает все входящие записи.
2.  **Настройка через Дашборд**:
    - На странице **Settings (Настройки)** пользователь управляет списком анализируемых номеров телефонов.
    - Там же настраиваются системные промпты (инструкции для LLM), по которым будет проводиться оценка.
3.  **Обработка истории**:
    - Для анализа старых записей на странице настроек создается "Задача" (Task) с указанием периода дат и нужного промпта.
4.  **Просмотр результатов**:
    - На странице **Analytics (Аналитика)** доступны графики распределения звонков по целям, вежливости и настроению.
    - Все графики интерактивны: клик по сегменту фильтрует общий список звонков.
    - В списке звонков можно просмотреть полный транскрипт и прослушать аудиозапись.
5.  **Мониторинг**:
    - Страница **Statistics (Статистика)** показывает текущую нагрузку на систему: сколько файлов в очереди, сколько обработано или пропущено.

## Требования
- **ОС**: Ubuntu 22.04+ (рекомендуется)
- **CPU**: 16+ ядер (рекомендуется)
- **RAM**: 32+ ГБ
- **ПО**: Python 3.12, ffmpeg, PostgreSQL 15+

## Установка и запуск

1.  **Подготовка**:
    ```bash
    git clone <repo_url>
    cd call_analysis
    ```

2.  **Автоматическая настройка**:
    Используйте скрипт для установки зависимостей, настройки окружения и подготовки моделей OpenVINO:
    ```bash
    sudo bash scripts/setup_ubuntu.sh
    ```

3.  **Конфигурация**:
    Скопируйте `.env.example` в `.env` и заполните параметры подключения к БД и пути к записям:
    ```bash
    cp .env.example .env
    nano .env
    ```

4.  **Запуск службы**:
    ```bash
    sudo systemctl enable --now call_analysis.service
    ```

5.  **Запуск дашборда**:
    ```bash
    streamlit run dashboard/dashboard.py
    ```

## Структура проекта
- `src/` — исходный код диспетчеров и воркеров.
- `dashboard/` — интерфейс на Streamlit.
- `scripts/` — скрипты для развертывания и запуска.
- `db/` — SQL-схемы для инициализации БД.
- `models/` — директория для весов моделей (GigaAM и Qwen2.5-OV).

## Конфигурация (.env)
- `RECORDS_ROOT` — путь к архиву записей (структура YYYY/MM/DD/*.mp3).
- `NUM_ASR_WORKERS` / `NUM_LLM_WORKERS` — количество параллельных процессов.
- `LLM_MODEL_PATH` — путь к сконвертированной OpenVINO модели.
